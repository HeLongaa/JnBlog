> 万象拼音是一套 **Rime 方案**（词库 + Lua + 388 MB 语法模型），在 macOS 上要跑在「小企鹅输入法（fcitx5-macos）」的**中州韵插件**里。这篇按实际操作顺序记一遍：装插件 → 部署方案 → 写配置 → 验证 → 两台 Mac 同步，顺带记下几个反直觉的坑（Shift 被两层同时绑定、候选数不能超过 6 个、升级后「看起来没生效」）。

## 为什么是这套组合

想要的是「类大厂」的整句候选 + 带调词库 + 简体输出，同时还要能自己改配置。可选方案其实就三个：

| 方案 | 优点 | 为什么不选 |
| --- | --- | --- |
| macOS 自带拼音 | 零成本、和系统深度整合 | 词库和整句排序明显落后，无法自定义 |
| 鼠须管（Squirrel） | 纯 Rime、生态最主流 | 外壳更新慢，配置改了要手动部署 |
| **fcitx5-macos + 中州韵 + 万象拼音** | 方案自由、Lua 扩展丰富、插件式可换方案 | 配置分散在几个地方，坑多（这篇主要就是填坑） |

## 一、先认清「两个小企鹅」

fcitx5-macos 有两个发行形态，**装错版本后面所有路径都不一样**：

- **拼音版**：自带 `chinese-addons`，输入法叫「拼音」，**不支持任何 Rime 方案**
- **Rime 版**：带「中州韵」插件（`librime.so`），万象跑在这上面

判断自己装的是哪个：

```bash
ls ~/Library/fcitx5/lib/fcitx5/
# 只有 libchineseaddons.so 之类 → 拼音版，需要补装中州韵
# 出现 librime.so → 已经是 Rime 版
```

### 补装中州韵插件（不需要 sudo）

插件装在用户目录，官方安装器的本质就是从这两个包里解压：

```bash
ARCH=$(uname -m); TAG=macos-0.4.2
curl -fL -o /tmp/rime-$ARCH.tar.bz2 \
  https://github.com/fcitx-contrib/fcitx5-plugins/releases/download/$TAG/rime-$ARCH.tar.bz2
curl -fL -o /tmp/rime-any.tar.bz2 \
  https://github.com/fcitx-contrib/fcitx5-plugins/releases/download/$TAG/rime-any.tar.bz2
mkdir -p ~/Library/fcitx5
tar xjf /tmp/rime-$ARCH.tar.bz2 -C ~/Library/fcitx5
tar xjf /tmp/rime-any.tar.bz2   -C ~/Library/fcitx5
```

`rime-any` 是各架构共用的资源（`rime-data`、图标、翻译），`rime-arm64`/`rime-x86_64` 里是 `librime.so` 本体，两个都要装。

### 要记住的四个路径

和 Linux 版一致，**不是**鼠须管的 `~/Library/Rime`：

| 用途 | 路径 |
| --- | --- |
| Rime 用户目录 | `~/.local/share/fcitx5/rime` |
| fcitx5 插件目录 | `~/Library/fcitx5` |
| fcitx5 配置 | `~/.config/fcitx5/` 下的 `profile`、`config` |
| 主程序 | `/Library/Input Methods/Fcitx5.app` |

## 二、部署流程

从[万象拼音仓库](https://github.com/amzxyz/rime-wanxiang)取 Base 包（`rime-wanxiang-base.zip`）和语法模型（`wanxiang-lts-zh-hans.gram`），解压进用户目录，然后重启 fcitx5 触发部署：

```bash
R=~/.local/share/fcitx5/rime
unzip -o rime-wanxiang-base.zip -d "$R"
cp wanxiang-lts-zh-hans.gram "$R"/
killall Fcitx5; open "/Library/Input Methods/Fcitx5.app"
```

几点必须知道：

- 包里**没有** `.gram`（388 MB 单独下载），不放进去万象也能用，但长句排序会明显变差
- 解压时别多套一层目录，`wanxiang.schema.yaml` 必须直接在 `$R` 下面
- 第一次部署要编译 51 MB 主词库，**耐心等 1~3 分钟**，中途别反复点「重新部署」
- 部署完成的标志是 `$R/build/wanxiang.table.bin`（约 58 MB）出现

```bash
ls -l ~/.local/share/fcitx5/rime/build/wanxiang.table.bin
```

### 坑 1：升级后「看起来没生效」

zip 内文件的修改时间是**打包时间**，可能比 `build/` 里的编译产物还早。升级版本时 Rime 对比时间戳，会判定「没变化，不用重编」——于是你换了新方案却毫无反应。

解决办法：自己记一个版本号，版本变化时清空 `build/` 强制重编。

```bash
VERFILE="$R/.wanxiang_version"
if [ "$(cat "$VERFILE" 2>/dev/null)" != "$VERSION" ]; then
  rm -rf "$R/build"
  echo "$VERSION" > "$VERFILE"
fi
```

### 坑 2：内存到底吃多少

「388 MB 语法模型」听着吓人，用 `vmmap` 实测：

| 场景 | 数据 |
| --- | --- |
| 稳态（部署完，不输入） | **Physical footprint 49 MB**（RSS 105 MB 里大部分是可回收的文件页） |
| 首次部署编译词库瞬间 | 峰值 **830 MB**，编完立刻释放 |
| 连打一长句之后 | `wanxiang.table.bin`（56 MB 映射）驻留 24.6 MB；`.gram`（388 MB 映射）驻留 70.8 MB |

`table.bin` 和 `.gram` 都是 **mmap 只读映射**，属于 clean page cache，系统缺内存时直接丢弃、下次缺页再读盘。所以常驻代价只有 **~50 MB**，和以前用 Luna 拼音没什么区别。唯一要注意的是重新部署会短暂飙到 800 MB 级别，别在那一刻开大型应用。

```bash
vmmap -summary "$(pgrep -f 'Fcitx5.app/Contents/MacOS/Fcitx5')" | grep 'Physical footprint'
```

## 三、配置：改哪几个文件

万象的配置是两层 patch 模型，很多「改了没反应」都是因为改错了文件：

| 文件 | 作用的原始文件 | 放什么 |
| --- | --- | --- |
| `default.custom.yaml` | `default.yaml`（全局：方案列表、菜单页大小、ascii_composer 等） | 全局行为、候选页大小 |
| `wanxiang.custom.yaml` | `wanxiang.schema.yaml`（方案：开关默认值、转写、词库挂接） | 简繁、双拼方案、自己的词库 |

`custom/` 目录里那些 `*.custom.yaml` 是**模板**，改了不生效；要复制到 `$R` 根目录才是正在使用的补丁。

### 3.1 默认简体

万象的简繁是 `[s2s, s2t, s2hk, s2tw]` 四个选项（简 / 通繁 / 港繁 / 臺繁），默认取第一个。想改默认值，用索引定位：

```yaml
# ~/.local/share/fcitx5/rime/wanxiang.custom.yaml
patch:
  switches/@7/reset: 0     # 0=简体 1=通繁 2=港繁 3=臺繁
  menu/page_size: 6
```

`@7` 是 `switches` 列表里那个选项组的序号（从 0 开始数），改之前先确认自己的版本里它还是第 8 项。另外注意 `default.yaml` 里有 `switcher/save_options`：**只要你在「万象状态面板」里手动切过一次简繁，那个选择就会被记住并覆盖 `reset`**，想回到「永远按 patch 说了算」就把 `user.yaml` 里多出来的 `options` 段删掉再部署。

### 3.2 候选数为什么只能到 6

万象把 `7 8 9 0` 拿去当**声调输入键**了。实测：

```text
keys=nihao   →  candidates(7): [1]你好 [2]你号 [3]拟好 [4]拟 [5]你 [6]泥 [7]腻
keys=nihao7  →  preedit=[ni hao¹]     ← 7 变成阴平声调，不是选第 7 个
```

所以 `menu/page_size: 7` 时第 7 个候选**按数字选不到**，只能用 `↓` 定位后空格上屏。官方注释写的就是「不得超过 6 个，7890 代表声调」，老老实实用 `6` 最省心。

### 3.3 让 Shift 只是上档键

「按 Shift 切中英」在这套组合里有**两个来源**，改一层不够：

| 层 | 默认值 | 表现 |
| --- | --- | --- |
| fcitx5 | `Hotkey/AltTriggerKeys = Shift_L`（源码默认，「按住 Shift 临时切换输入法」） | 组里有多个输入法时，Shift 在两个输入法之间轮换 |
| Rime | `ascii_composer/switch_key: {Shift_L: commit_code, Shift_R: commit_code}` | 切到 Rime **内建**的英文模式 |

macOS 的习惯是「输入法自己不管中英，切输入源用 Caps Lock / Ctrl+Space」，所以两层都要关：

```yaml
# ① Rime 层：~/.local/share/fcitx5/rime/default.custom.yaml
patch:
  ascii_composer/switch_key/Shift_L: noop
  ascii_composer/switch_key/Shift_R: noop
  ascii_composer/switch_key/Caps_Lock: noop
```

```ini
; ② fcitx5 层：~/.config/fcitx5/config
; 换成一个 Mac 键盘上不存在的键 = 事实上禁用
[Hotkey/AltTriggerKeys]
0=Zenkaku_Hankaku
```

改完 `killall Fcitx5` 重启，打英文就走 macOS 自己的 ABC 了。

顺便把输入法列表也收干净——`~/.config/fcitx5/profile` 里只留「中州韵 + 键盘布局」，第二个中文输入法都没了，Shift 自然也无从轮换。

### 3.4 常用快捷键

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl + \`` | 万象状态面板（切简繁、声调显示、字符集、中英） |
| `/pinyin` `/flypy` `/zrm` | 在输入框里直接切全拼 / 小鹤 / 自然码 |
| `-` `=` | 上下翻页（也可用 PageUp/PageDown） |
| `Ctrl + Shift + 4` | 切换简繁 |

## 四、怎么证明它真的生效

不想靠肉眼「感觉候选变好了」，可以直接用 fcitx5 自带的 `librime.so` 跑一个无 UI 会话。它是 fcitx 插件（`MH_BUNDLE`），不能直接链接，但可以 `dlopen`：

```c
void *h = dlopen("/path/to/librime.so", RTLD_LAZY);
RimeApi *api = ((RimeApi *(*)(void))dlsym(h, "rime_get_api"))();

RIME_STRUCT(RimeTraits, t);
t.shared_data_dir = "/Users/<you>/Library/fcitx5/share/rime-data";
t.user_data_dir   = "/Users/<you>/.local/share/fcitx5/rime";
t.app_name = "rime.test"; t.log_dir = "";
api->setup(&t); api->initialize(&t);
api->start_maintenance(True);
while (api->is_maintenance_mode()) api->join_maintenance_thread();

RimeSessionId s = api->create_session();
api->select_schema(s, "wanxiang");
api->simulate_key_sequence(s, "neijuan");
```

唯一的小坑：这个 `.so` 依赖 fcitx 主程序里的 3 个 UI 符号，headless 环境要先用 stub dylib 补上：

```c
int f5m_is_linear_layout(void *a, void *b) { return 0; }
int f5m_is_vertical_lr(void *a, void *b) { return 0; }
int f5m_is_vertical_rl(void *a, void *b) { return 0; }
```

`DYLD_INSERT_LIBRARIES=stub.dylib` 之后就能跑，实测输出：

```text
keys=neijuan   preedit=[nei juan]   [1]内卷 [2]内聚 …
keys=maodie    preedit=[mao die]    [1]耄耋 …
keys=taotie    preedit=[tao tie]    [1]饕餮 …
```

再配合 `lsof` 看进程真的 mmap 了哪些文件：

```bash
lsof -p <pid> | grep -E 'wanxiang.*(gram|table\.bin)'
```

看到 `wanxiang-lts-zh-hans.gram`（407,160,876 B）和 `wanxiang.table.bin`（58,714,452 B）都在，才敢说「词库和语法模型都进了内存」。

## 五、多设备同步

这是最容易翻车的一环。核心原则：**三类数据三种同步方式，绝不能混在一起。**

| 数据 | 位置 | 同步方式 |
| --- | --- | --- |
| 用户词 / 自造词 | `wanxiang.userdb`（运行中的 rocksdb） | **Rime 原生同步**，导出文本到 `sync_dir` |
| 个人配置（custom patch、短语、自建词库） | 若干 `*.custom.yaml` | **git 仓库** |
| 方案本体 + 388 MB 语法模型 | release zip + `.gram` | **每台机重新下载**，不进任何同步 |

**不要**用 iCloud / OneDrive 实时同步整个 `rime` 目录：`wanxiang.userdb` 是正在被锁定的数据库，网盘抓取会造成文件锁，轻则同步失败，重则词库损坏。

### 5.1 配置：git 仓库管住

只把「自己改过的」文件放进仓库，方案本体交给脚本重新下载：

```text
rime-config/
├── install.sh                      # 一键部署（幂等，可反复跑）
└── personal/
    ├── rime/wanxiang.custom.yaml    # 简体默认、候选数
    ├── rime/default.custom.yaml     # Shift/noop
    ├── rime/custom_phrase.dict.yaml # 固定短语（邮箱、签名、地址）
    └── fcitx5/{profile,config}      # 输入法列表、快捷键
```

注意仓库里**不要**出现 `build/`、`*.userdb/`、`*.gram`、`dicts/`：前两个是运行时产物，后两个是几百 MB 的静态资源，进 git 只会让仓库变肿。

### 5.2 用户词：Rime 原生同步

编辑 `~/.local/share/fcitx5/rime/installation.yaml`：

```yaml
installation_id: "Mac-mini"     # 每台机必须不同！
sync_dir: "/Users/lumocore/Library/Mobile Documents/com~apple~CloudDocs/rime-sync"
```

然后把 `sync_dir` 指向 iCloud Drive 里的一个共享目录（用 Syncthing 也行），每台机器点一次「菜单栏 Fcitx5 → 中州韵 → 同步」，会产生：

```text
rime-sync/
├── Mac-mini/wanxiang.userdb.txt      # 里面有 #@/tick 和 #@/user_id
└── MacBookpro/wanxiang.userdb.txt
```

四个必须知道的细节：

1. `installation_id` 两台机**绝不能相同**，否则会互相覆盖
2. 同步是「导出自己的 + 读取所有设备目录合并」，所以是个**往返**过程：A 同步 → B 同步 → **A 再同步一次**才完全对齐
3. 不要两台同时点；同步本身只要几秒，但 iCloud 传输有延迟，等目录里文件变成实体（不是云端占位符）再操作
4. 同步目录里的 `*.yaml` 只是**快照备份**，Rime 只合并 `*.userdb.txt`，**不会**把快照写回你的配置——这点很容易误解

### 5.3 怎么确认同步真的成功

```bash
# tick 越大越新；合并后条数会增加
grep -E '^#@/(tick|user_id)' "$SYNC/Mac-mini/wanxiang.userdb.txt"
grep -c '^[^#]' "$SYNC/Mac-mini/wanxiang.userdb.txt"
```

如果读 iCloud 里的文件报 `Resource deadlock avoided`，说明那个文件还是云端占位符（iCloud 正在传），等它落地再看。

## 六、最后打包成一键脚本

坑踩完之后，把上面所有动作塞进 `install.sh`，新机器三条命令：

```bash
git clone https://github.com/HeLongaa/rime-config ~/rime-config
cd ~/rime-config
./install.sh --id MacBookpro
```

脚本做四件事，都是幂等的：

1. **静态资源**：按版本号下载方案包和 `.gram` 到 `~/rime-dist` 缓存，解压进 `$R`；版本变化时清 `build/` 强制重编
2. **个人配置**：把 `personal/rime/*` 覆盖进 `$R`，`personal/fcitx5/*` 覆盖进 `~/.config/fcitx5`（已存在则跳过，避免踩掉本机设置）
3. **行为对齐**：把 `rime` 补进输入法列表、摘掉其它中文输入法、把 `AltTriggerKeys` 换成 `Zenkaku_Hankaku`
4. **重新部署**：`killall Fcitx5` + 重启，用 marker 时间戳等到 `build/wanxiang.schema.yaml` 刷新才算完成

日常维护就三句话：

```bash
git pull && ./install.sh --id <本机名>   # 拉新配置
# 改 WANXIANG_VERSION 后两台各跑一次      # 升级万象
# 菜单栏 → 中州韵 → 同步                  # 同步自造词
```

## 用下来的感受

- **候选质量**：整句输出现代词（内卷、躺平、饕餮）准确率明显高于自带拼音，语法模型对长句的帮助能感知到
- **代价**：常驻 ~50 MB 内存（可接受）、首次部署 1~3 分钟、磁盘 ~540 MB（词库 + 模型 + 编译产物）
- **最烦的**：声调键占了 `7890`，候选选择被压缩到 6 个，习惯了大候选窗的人需要适应
- **最爽的**：全部配置都是纯文本，改一行 yaml 就是一次可版本化的改动，两台机器状态完全一致
